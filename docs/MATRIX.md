# Capability matrix: five types, seven operations, six serializations

Generated by `scripts/make-matrix.mjs` from `src/types.js`, `src/drafts.js` and the
provenance files. Do not edit the grids: edit the tables they come from, then run
`npm run matrix`. CI runs `npm run check:matrix`, which fails when this file and the
code disagree in either direction - a claim the code does not support, or a
capability the code has and the documentation does not mention.

Baseline: FAIR-bioHeaders-Specification v0.6.0 - FHR '2.1', FHP '1.2', FHGFF3 '1.2'.

## How to read a cell

| Mark | Meaning |
| --- | --- |
| `yes` | implemented here, checked by the native test suite |
| `draft lane` | implemented here, but only where the caller passed `{drafts: [...]}`; the result is labelled draft and is never a released-contract result |
| `no` | not implemented: `not-supported-yet`, with the reason in the footnote |
| `n/a` | the cell is not a gap: the dimension does not apply to that type or serialization, and the footnote says who owns it |

## Draft-lane rules, by name

FHT's rules are C1 to C3 and FHGM's are B1 and K1 to K6, drafted in their own
repositories.

The lane reads two pinned things and they are separate claims: the contract bytes at
`226f923c28b680edb3c546e99a751482d06aef1a` (sha256 `59ad9641adcb0e55…`), and the development suite this
build verifies at `24d3b033ab951ef79ee9f6d17419d8ba700f1b0a` - manifest `conformance/manifest.json`, sha256
`9b07179497bdc724…`, 66 vectors, whose three contract
rules carry the C1/C2/C3 ids listed below. The guard is
`scripts/ci/suite-pin.mjs`, and it refuses any other suite revision, so no draft
count in this repository is attributed to a revision that was never checked.

FHGM states no suite pin in `drafts/provenance.json`, so its draft-lane run is
labelled `UNPINNED`: the numbers it prints describe the checkout it was handed,
and this build makes no claim about which revision that was.

Which of the rules run here, and which do not:

| rule | type | here | what it covers, or why it does not run |
| --- | --- | --- | --- |
| C1 | FHT | yes | the parsed metadata validates against the pinned `fht.json` |
| C2 | FHT | yes | schema-URL closure, inside the pinned bytes: another type's URL or an arbitrary URL fails the contract and never selects FHT |
| C3 | FHT | yes | parent-link verdicts `checked-pass` / `checked-fail` / `unchecked`, against parent bytes the caller supplies; never assumed, never invented |
| B1 | FHGM | yes | the released FHGFF3 schema and the exact-byte checksum must hold before any model verdict exists; with them false the verdict is `not-checked` |
| K1 | FHGM | yes | transport: R15 admits extension fields from FHGFF3 1.1, and `x-fhgm-models` holds one or more records. `overlay: true` also applies the pinned transport overlay, which is narrower: it names the v0.5.0 citation and 1.1 outright |
| K2 | FHGM | yes | every record validates against the pinned record contract (`modelId`, `modelVersion`, `featureId`, `reference` required, objects closed) |
| K3 | FHGM | yes | `modelId` unique within a snapshot; a shared id is ambiguous and rejects that snapshot, current or supplied predecessor |
| K4 | FHGM | no | K4 resolves a record featureId, percent-decoded, to exactly one local gene row, which needs the GFF3 feature layer; this library reads the FHGFF3 header and nothing below it, so feature lines belong to gff3-validator |
| K5 | FHGM | yes | a record reference shares at least one comparable form with the file genome link and never contradicts it |
| K6 | FHGM | yes | predecessor verdicts `resolvable` / `unresolvable` / `ambiguous`, against explicitly supplied prior snapshots only |

The rule ids this module knows are B1, K1, K2, K3, K4, K5, K6; the ones that run are B1, K1, K2, K3, K5, K6.

## What a lane reading says

A V7 reading is distinguishable from a released one in three places, all of them
machine-checkable (`test/draft-lane.test.mjs`):

```json
{
  "schema": { "type": "FHT", "release": null, "schemaVersion": null, "rule": "V7" },
  "warnings": [
    "FHT: warning: schema https://raw.githubusercontent.com/FAIR-bioHeaders/FHT-Specification/main/fht.json is an unreleased draft (commit 226f923c28b680edb3c546e99a751482d06aef1a, sha256 59ad9641adcb0e5591045c2d894c066d1adc9984cca84c5ff6502f8dad88487e of those bytes); read against that pinned draft, not a released schema"
  ]
}
```

- `rule` is `V7`, not a release rule;
- `release` and `schemaVersion` are `null`, because a draft has taken neither form;
- the warning names the citation, the commit and the digest the bytes were read at.

For FHGM there is no `schema` change to see, because the file is a released FHGFF3
file: its records are judged in a separate `fhgm` block, and the FHGFF3 result is
identical to what the same bytes produce with the lane shut
(`test/fhgm.test.mjs` asserts both halves of that).
